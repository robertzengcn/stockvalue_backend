   - `app_with_admin`: Includes admin_router, overrides get_db with mock, overrides get_current_user to return admin dict (role="admin")
   - `admin_client`: AsyncClient with app_with_admin
   - `app_with_regular_user`: Same but get_current_user returns regular user dict (role="user")
   - `regular_client`: AsyncClient with app_with_regular_user

   IMPORTANT: Override `get_current_user` not `require_admin` -- this tests the full middleware chain. Use the exact same override pattern as test_auth_flow.py:
   ```python
   from stockvaluefinder.api.dependencies import get_current_user
   app.dependency_overrides[get_current_user] = lambda: {
       "user_id": str(admin_user_id),
       "email": "admin@test.com",
       "role": "admin",
       "is_active": True,
   }
   ```
   For the regular user fixture, set role="user". The require_admin dependency will then raise 403.

   NOTE: The lambda must be `lambda: {...}` (sync function) because get_current_user returns a dict directly in the override (same pattern as test_auth_flow.py). However, get_current_user is async, so the override should match. Use `AsyncMock` or an async function:
   ```python
   async def _admin_override():
       return {"user_id": str(admin_user_id), "email": "admin@test.com", "role": "admin", "is_active": True}
   app.dependency_overrides[get_current_user] = _admin_override
   ```

       user.created_at = datetime(2026, 1, 1)
