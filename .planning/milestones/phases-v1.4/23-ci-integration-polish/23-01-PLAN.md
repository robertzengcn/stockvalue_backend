Create `stockvaluefinder/stockvaluefinder/tools/validate_registry.py`:

A standalone script that validates `metric_registry.yaml` against the Pydantic schema. This catches registry drift (missing tolerance, invalid formula reference, broken depends_on) before tests execute.

```python
"""Validate metric_registry.yaml against the Pydantic schema.

Exits 0 if valid, 1 if invalid. Prints validation summary to stdout.
Designed for use as a pre-commit hook and CI early-check step.

Usage::

    uv run python -m stockvaluefinder.tools.validate_registry
    uv run python stockvaluefinder/tools/validate_registry.py
"""
```

Implementation:
1. Use `MetricRegistry.from_yaml_file()` to load and validate the YAML. The YAML path is resolved relative to the script location: `Path(__file__).parent.parent / "validation" / "metric_registry.yaml"`.
2. On success: print summary showing total metrics count, categories breakdown, P0/P1/P2 counts.
3. On `pydantic.ValidationError`: print the error details and exit 1.
4. On `FileNotFoundError`: print error and exit 1.
5. Add a `main()` function and `if __name__ == "__main__"` block.
6. No external dependencies beyond what's already in pyproject.toml (pydantic, yaml).

Then update `stockvaluefinder/.pre-commit-config.yaml` to add a new hook:

```yaml
      - id: validate-registry
        name: validate metric registry YAML
        entry: bash -c "cd stockvaluefinder && uv run python stockvaluefinder/tools/validate_registry.py"
        language: system
        pass_filenames: false
        always_run: true
```

Add this hook AFTER the existing ruff-format hook. The `always_run: true` ensures it runs even if metric_registry.yaml is not in the staged files (because a change to schema.py could break the registry without touching the YAML).

Run the validation script manually to confirm it passes:
```bash
uv run python stockvaluefinder/tools/validate_registry.py
```
