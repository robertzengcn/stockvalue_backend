Create `doc/validation_guide.md` at the repository root. This is the comprehensive documentation for the 3-layer validation system. Write it in clear, technical English (matching the codebase convention of English for code/internal, Chinese for user-facing).

The document must cover these 5 sections:

**Section 1: System Overview**
- Describe the 3-layer validation pyramid:
  - L1 Formula: Pure `calculate_*` function verification against published paper values
  - L2 Mapping: AKShare field extraction and cross-source consistency verification
  - L3 Golden: End-to-end pipeline from frozen data through calculation to expected values
- Explain the metric registry (`metric_registry.yaml`) as the single source of truth
- List the 28 metrics across 7 categories (risk, roic, valuation, yield, capex, policy, alpha)
- Note priority levels: P0 (M-Score, ROIC), P1 (WACC, FCF, Yield, CapEx), P2 (Policy, Alpha)

**Section 2: Running Tests**
- How to run each layer locally:
  - `uv run pytest -m l1_formula` -- fast, no I/O, pure function tests
  - `uv run pytest -m l2_mapping` -- frozen JSON, no network
  - `uv run pytest -m golden` -- frozen JSON, no network
  - `uv run pytest -m golden_live` -- requires network, hits real AKShare
- How to run all validation tests: `uv run pytest -m "l1_formula or l2_mapping or golden"`
- How to run tests for a specific stock: `uv run pytest tests/golden/test_l3_golden.py -k "600519"`
- CI integration: GitHub Actions runs l1/l2/golden on every PR, golden_live weekly

**Section 3: Reconcile CLI**
- Document all CLI flags with examples:
  - Basic: `uv run python -m stockvaluefinder.tools.reconcile --ticker 600519.SH --year 2023`
  - Single metric: `--metric m_score`
  - Verbose audit trail: `--verbose`
  - JSON output: `--json`
  - Live mode: `--live` (fetches real AKShare data)
- Explain exit codes: 0 (all P0 pass), 1 (P0 failure), 2 (error)
- Note that `--live` requires network and AKShare availability

**Section 4: Contributing New Golden Stocks**
Step-by-step guide:
1. Add entry to `tests/golden/manifest.yaml` with ticker, sector, is_financial, years, l3_verified=false
2. Run `uv run python tests/golden/freeze_akshare_data.py <TICKER>` to fetch and freeze AKShare data
3. Run `uv run python tests/golden/compute_golden_values.py <TICKER> <YEAR>` to generate expected_metrics.yaml template
4. Manually verify values against annual report/CNINFO -- update expected_metrics.yaml
5. Write provenance.md documenting the source (annual report page, line item)
6. Run `uv run pytest tests/golden/test_l3_golden.py -k "<TICKER>"` to verify
7. Set l3_verified=true in manifest.yaml
8. Commit all new files

**Section 5: Tolerance Configuration Reference**
- Explain tolerance types in metric_registry.yaml:
  - `absolute`: Fixed delta tolerance (e.g., 0.05 for M-Score means computed can differ by up to 0.05)
  - `relative`: Percentage tolerance (e.g., 0.02 means 2% relative difference allowed)
  - Both can be specified; the comparison passes if either threshold is met
- Table of current tolerances by metric category:
  - Risk: absolute 0.05 (sub-indices), 0.01 (goodwill, divergence)
  - ROIC: relative 0.02 (NOPAT, invested capital), 0.01 (ROIC spread)
  - Valuation: relative 0.01-0.02 (WACC, PV, TV, MoS)
  - Yield: relative 0.01
  - CapEx: relative 0.01, absolute 0.5 (score)
  - Policy: absolute 1.0 (score), 0.001 (DCF adjustment)
  - Alpha: absolute 0.1
- F-Score special case: absolute 0 (exact integer match required)
- How to modify: edit metric_registry.yaml, validation is automatic via pre-commit hook

Keep the document focused and practical. No fluff, no motivational prose. This is a reference document for developers who need to use or extend the system.
