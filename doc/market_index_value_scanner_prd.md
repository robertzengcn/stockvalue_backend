# PRD：指数池价值扫描器（Market Index Value Scanner）

**版本**：V1.0  
**日期**：2026-06-04  
**目标目录**：`stockvalue_backend/doc`  
**适用产品**：StockValueFinder  

---

## 1. 产品背景

StockValueFinder 已经具备单股分析能力，包括 DCF 估值、风险排雷、股息收益率对比、ROIC-WACC、资本分配、政策共振和 Alpha 综合评分。当前能力更偏向“用户输入一个股票代码后进行分析”或“关注列表公告更新后触发分析”。

下一阶段需要从“被动分析单个标的”升级为“主动发现潜在低估机会”。用户不应该每天手工筛选几百只股票，而应该让系统在可靠股票池中定时扫描，找出值得进一步研究的候选标的。

本 PRD 建议新增 **指数池价值扫描器**：定时扫描沪深 300、中证 500 等指数成分股，发现估值可能低于内在价值、且基本面质量和风险可接受的股票，形成可解释的候选清单。

---

## 2. 产品目标

### 2.1 核心目标

在沪深 300、中证 500 这类指数池内，自动发现“疑似低估且值得进一步研究”的股票，并用结构化证据解释入选原因。

### 2.2 非目标

V1 不直接提供买卖建议，不输出“推荐买入”“目标价买入”等投顾式结论。系统定位为投资辅助工具，只提供筛选、估值、风险提示和分析证据。

V1 不扫描 A 股/H 股全市场。全市场扫描会显著增加数据压力、限流风险、误报率和运维复杂度，应在指数池版本稳定后再扩展。

V1 不承诺实时盘中交易信号。第一版以收盘后扫描和周末深度扫描为主。

---

## 3. 目标用户

### 3.1 主要用户

- 关注 A 股价值投资的个人投资者
- 需要定期寻找低估股票的严肃投资者
- 已经维护自选股，但希望系统主动补充候选标的的用户

### 3.2 用户痛点

- 沪深 300、中证 500 合计股票数量较多，人工筛选耗时
- 低 PE、低 PB 股票中存在大量价值陷阱
- 单看价格下跌无法判断是否真的低估
- 财报、现金流、风险指标和股息回报分散在不同数据源中
- 用户需要“为什么入选”的证据，而不是一个黑箱分数

## 4. 范围定义

### 4.1 V1 扫描范围

V1 支持以下指数池：

- 沪深 300（CSI300）
- 中证 500（CSI500）

系统应支持后续扩展到：

- 中证 1000
- 中证红利
- 行业主题指数
- 用户自定义股票池

### 4.2 V1 分析范围

V1 重点识别以下类型的机会：

- DCF 安全边际较高的低估股票
- 股息收益率显著高于无风险收益率的高股息股票
- ROIC-WACC 为正且估值处于低位的优质企业
- Alpha Score 较高但市场价格回落的候选标的

V1 重点过滤以下风险：

- 财务操纵风险偏高
- 现金流质量差
- 经营恶化导致的“便宜陷阱”
- 高杠杆且偿债压力偏大
- 数据缺失或数据质量不足

## 5. 核心产品形态

### 5.1 指数池价值雷达

系统每日收盘后自动扫描沪深 300、中证 500 成分股，生成当日候选清单。候选清单应按综合吸引力排序，但必须展示每只股票的关键证据。

### 5.2 候选股票详情

用户点击候选股票后，可以看到：

- 当前价格
- 估算内在价值
- 安全边际
- 估值等级
- Alpha 综合评分
- 风险评分或风险等级
- 股息收益率与无风险收益率差
- 所属指数
- 入选原因
- 主要风险提示
- 数据更新时间
- 计算审计轨迹

### 5.3 加入关注列表

用户可以将候选股票加入已有 watchlist。加入后，该股票应进入现有持续跟踪流程，在新财报、新公告或价格大幅变化时触发后续分析。

## 6. 扫描漏斗设计

V1 采用三层漏斗，避免对所有股票直接运行高成本深度分析。

### 6.1 第一层：市场粗筛

目标是快速排除明显不适合进入深度估值的股票。

建议条件：

- 剔除 ST、停牌、退市风险警示股票
- 剔除流动性显著不足的股票
- 剔除关键行情数据缺失的股票
- 剔除近年经营现金流持续为负且无合理解释的股票
- 优先保留低 PE、低 PB、高股息率、低估值分位、价格回撤明显的股票

第一层输出不应直接展示给用户，只作为深度分析候选输入。

### 6.2 第二层：价值确认

目标是判断价格是否相对内在价值有足够安全边际。

应复用现有 DCF 估值能力，计算：

- 当前价格
- 内在价值
- WACC
- 安全边际
- 估值等级

建议 V1 默认阈值：

- 安全边际 `>= 30%`：疑似低估
- 安全边际 `-30% ~ 30%`：合理估值
- 安全边际 `<= -30%`：疑似高估

阈值需要配置化，不能写死在业务代码中。

### 6.3 第三层：质量与风险复核

目标是避免把“质量恶化导致的便宜”误判为投资机会。

建议复核维度：

- ROIC-WACC 是否为正
- Alpha Score 是否达到候选阈值
- M-Score 是否提示财务操纵风险
- 经营现金流与净利润是否长期背离
- 资产负债率和利息覆盖是否处于危险区
- 股息收益率是否显著高于无风险收益率
- 股息是否具有可持续性

只有通过风险复核的股票，才能进入最终候选清单。

## 7. 候选评分模型

### 7.1 V1 综合排序建议

候选股票可按综合分排序，综合分仅用于排序，不应作为投资建议。

建议权重：

| 维度 | 权重 | 说明 |
| --- | ---: | --- |
| 安全边际 | 35% | 低估程度是核心信号 |
| Alpha Score | 25% | 质量、资本效率和成长线索 |
| 风险扣分 | 20% | 财务操纵、现金流、杠杆等 |
| 股息收益率差 | 10% | 高股息机会成本优势 |
| 估值历史分位 | 10% | 当前估值相对历史位置 |

### 7.2 解释要求

每只候选股票必须生成结构化入选原因，例如：

```text
入选原因：
- 安全边际 38%，高于 30% 阈值
- ROIC-WACC 为正，企业仍在创造超额回报
- PB 处于近五年偏低分位
- 股息收益率高于十年期国债收益率

主要风险：
- 最近一期存货周转放缓
- 经营现金流覆盖净利润能力较去年下降
```

解释应由确定性数据和已计算指标驱动。LLM 可以参与自然语言润色，但不能凭空生成财务结论。

## 8. 定时策略

### 8.1 每日轻量扫描

运行时间：每个交易日收盘后。  
目标：更新行情、基础估值指标和候选初筛结果。

建议行为：

- 同步指数成分股
- 拉取最新价格和基础行情
- 运行第一层市场粗筛
- 对粗筛 Top N 运行价值确认
- 更新候选清单

### 8.2 周末深度扫描

运行时间：每周末。  
目标：对候选池做更完整的质量、风险和估值复核。

建议行为：

- 补齐财报数据
- 运行 DCF、风险排雷、收益率差、Alpha 综合评分
- 重算候选排序
- 生成本周候选变化摘要

### 8.3 事件触发重扫

以下事件发生时，应触发单股重扫：

- 股票发布年报、半年报、季报或修订公告
- 当前价格较上次深度扫描下跌超过配置阈值，例如 10%
- 指数成分股发生调整
- 用户将候选股票加入 watchlist

## 9. 数据需求

### 9.1 输入数据

| 数据 | 用途 |
| --- | --- |
| 指数成分股 | 确定扫描范围 |
| 实时或收盘价格 | 估值、安全边际、股息率计算 |
| 财务报表 | DCF、风险、ROIC、现金流质量 |
| 股本数据 | 每股内在价值计算 |
| 股息数据 | Yield Gap 和高股息筛选 |
| 无风险利率 | WACC、机会成本对比 |
| 行业分类 | 行业相对估值和风险分层 |

### 9.2 数据源建议

优先复用现有外部数据服务。当前项目已有 AKShare、efinance、Tushare fallback 思路，可在扫描器中继续沿用多源策略。

V1 不应为扫描器单独引入完全不同的数据源体系，除非现有数据服务无法覆盖指数成分股或关键行情字段。

## 10. 功能需求

### FR-01 指数成分股同步

系统应支持同步沪深 300、中证 500 成分股，并记录生效日期。

验收标准：

- 可以查询某个指数当前有效成分股
- 可以保留成分股历史变更记录
- 同一股票可同时属于多个指数
- 同步失败时保留上一次可用成分股池

### FR-02 定时扫描任务

系统应支持后台定时扫描指数池。

验收标准：

- 每日轻量扫描可以独立运行
- 周末深度扫描可以独立运行
- 扫描任务具备唯一 run id
- 扫描失败不会影响现有财报 watcher 和 pipeline worker
- 扫描状态可查询

### FR-03 粗筛规则配置

系统应支持配置筛选阈值。

验收标准：

- 安全边际阈值可配置
- Top N 深度估值数量可配置
- 风险排除阈值可配置
- 指数池可配置
- 配置变更不需要修改业务代码

### FR-04 深度估值与风险复核

系统应对粗筛结果运行深度分析。

验收标准：

- 复用现有 DCF 估值逻辑
- 复用现有风险分析逻辑
- 复用现有 Yield Gap 逻辑
- 复用现有 Alpha Score 逻辑
- 任一分析模块失败时，候选记录应保留失败原因，而不是整批任务失败

### FR-05 候选清单生成

系统应生成最终候选清单。

验收标准：

- 每次扫描生成独立候选结果
- 候选结果包含所属指数、综合分、排名和入选原因
- 候选结果包含主要风险提示
- 支持按扫描时间、指数、估值等级、风险等级过滤

### FR-06 候选加入 watchlist

用户应能将候选股票加入关注列表。

验收标准：

- 已存在 watchlist 的股票不重复添加
- 新加入股票沿用现有 watchlist 行为
- 加入后可触发或等待后续持续跟踪

### FR-07 前端展示

前端应新增“价值雷达”或“候选池”视图。

验收标准：

- 展示最近一次扫描摘要
- 展示候选股票列表
- 支持指数筛选
- 支持按安全边际、综合分、风险等级排序
- 展示每只股票入选原因和风险提示
- 提供加入 watchlist 操作

## 11. 非功能需求

### 11.1 性能

- 每日轻量扫描应在可接受时间内完成，建议目标小于 30 分钟
- 周末深度扫描可耗时更长，但应支持任务进度和失败重试
- 对外部 API 请求必须限流，避免数据源封禁

### 11.2 稳定性

- 单只股票失败不影响整批扫描
- 数据源不可用时应记录失败原因，并尽可能使用缓存或备用源
- 扫描任务应幂等，重复执行同一 run 不应产生重复候选

### 11.3 可审计性

- 每个候选结果必须记录计算使用的关键输入
- 每个候选结果必须记录分析时间
- 每个候选结果必须记录规则版本
- 每个候选结果必须可追溯到 scan run

### 11.4 合规

- 页面和接口文案应避免“买入建议”“收益承诺”等表达
- 候选清单应明确标注为“研究候选”或“投资辅助筛选”
- AI 生成解释必须基于已有指标和审计轨迹

## 13. 建议 API

以下为建议新增接口，不代表当前系统已经存在。

### 13.1 查询最近扫描结果

```http
GET /api/v1/market-scanner/runs/latest?index_code=CSI300
```

返回最近一次扫描摘要和候选数量。

### 13.2 查询扫描任务列表

```http
GET /api/v1/market-scanner/runs
```

支持按扫描类型、状态、日期过滤。

### 13.3 查询候选清单

```http
GET /api/v1/market-scanner/candidates?run_id={run_id}&index_code=CSI500
```

支持排序和分页。

### 13.4 查询候选详情

```http
GET /api/v1/market-scanner/candidates/{candidate_id}
```

返回入选原因、风险提示和审计轨迹。

### 13.5 手动触发扫描

```http
POST /api/v1/market-scanner/runs
```

仅管理员或授权用户可用。

### 13.6 将候选加入 watchlist

```http
POST /api/v1/market-scanner/candidates/{candidate_id}/watchlist
```

将候选股票加入现有关注列表。

## 15. 成功指标

### 15.1 产品指标

- 每日扫描成功率 >= 95%
- 候选清单生成时间满足每日使用需求
- 用户将候选加入 watchlist 的转化率
- 用户查看候选详情的点击率

### 15.2 分析质量指标

- 候选股票中数据完整率
- 候选股票风险误报率
- 候选股票后续被剔除的原因分布
- 入选原因可解释覆盖率

### 15.3 工程指标

- 单股失败不影响整批扫描
- 外部数据源失败有明确日志和状态记录
- 扫描任务可重试
- 候选结果可追溯到规则版本和计算输入

## 16. 风险与对策

### 16.1 数据源限流

风险：指数池扫描会集中请求大量行情和财务数据。  
对策：使用分层扫描、缓存、请求限流和多源 fallback；只对 Top N 做深度分析。

### 16.2 误报价值陷阱

风险：低 PE、低 PB 可能来自基本面恶化。  
对策：必须叠加现金流质量、ROIC-WACC、M-Score、负债风险和 Alpha Score。

### 16.3 DCF 参数敏感

风险：DCF 结果对增长率、WACC、终值增长率敏感。  
对策：默认展示关键参数和敏感性提示；候选判断不要只依赖单一 DCF 输出。

### 16.4 指数成分股调整

风险：指数成分股会定期调整，写死股票池会导致扫描范围失真。  
对策：成分股必须可同步、可追溯、可保留历史。

### 16.5 合规表达

风险：候选清单容易被理解为投资建议。  
对策：统一使用“候选”“研究线索”“风险提示”等表达，避免买卖指令。

## 17. V1 验收清单

- [ ] 系统可以同步沪深 300、中证 500 成分股
- [ ] 系统可以定时运行每日轻量扫描
- [ ] 系统可以生成独立扫描 run
- [ ] 系统可以保存候选股票结果
- [ ] 候选结果包含安全边际、估值等级、Alpha 分、风险提示
- [ ] 候选结果包含结构化入选原因
- [ ] 单只股票分析失败不会导致整批失败
- [ ] 用户可以在前端查看候选池
- [ ] 用户可以将候选股票加入 watchlist
- [ ] 页面和接口文案符合投资辅助工具定位

## 18. 推荐 MVP 结论

第一版建议聚焦：

```text
沪深 300 / 中证 500
+ 每日收盘后扫描
+ Top N 深度估值
+ 可解释低估候选清单
+ 加入 watchlist 持续跟踪
```

这条路径最符合当前系统已有能力，也能在成本、数据质量、用户价值之间取得平衡。等指数池版本稳定后，再扩展到全市场扫描、行业轮动扫描和主动提醒。
